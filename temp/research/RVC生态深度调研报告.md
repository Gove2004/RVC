## 一、RVC 原版技术架构

### 核心流程
1. **HuBERT 特征提取**：输入音频 → HuBERT base/large → 768维内容特征（50fps）
2. **F0 提取**：RMVPE / FCPE / Harvest / Crepe → 音高曲线
3. **Faiss 特征检索**：训练集特征索引 → 相似度匹配 → 混合输入特征与目标特征
4. **NSF HiFiGAN 合成**：特征 + F0 + spk → 音频波形（模型采样率）

### 性能指标
| 指标 | 标准配置 | ASIO 优化 |
|------|---------|-----------|
| 端到端延迟 | ~170ms | ~90ms |
| 训练时间（10min数据） | ~18min (RTX 3090) | - |
| 最低训练数据 | 1min | - |
| 训练显存 | 4GB | - |

### F0 提取器对比
| 提取器 | 速度 | 质量 | GPU占用 | 推荐度 |
|--------|------|------|---------|--------|
| RMVPE | 快 | 最好 | 极低 | ⭐⭐⭐⭐⭐ |
| FCPE | 略快于RMVPE | 略差 | 低 | ⭐⭐⭐⭐ |
| Harvest | 慢 | 一般 | CPU | ⭐⭐ |
| Crepe | 慢 | 一般 | 高 | ⭐ |

## 二、套皮项目深度分析

### 2.1 心月变声器

**核心卖点：**
1. **自研咬字算法**（默认开启）
   - 连续读同音字/相同音不跑调
   - 解决"宝宝→粑粑"、"凤凰→凤翔"问题
   - 技术推测：特征时间轴校正 + 输入侧特征归一化

2. **空气感效果**（独家）
   - 增加声音亮度和通透感
   - 离线翻唱也能继承质感
   - 技术推测：高频段 EQ 提升（6-16kHz）+ 频谱倾斜

3. **内置 AI 降噪**
   - 纯 CPU 运行，0 GPU 占用
   - 不吞字（对比 NVIDIA Broadcast GPU 降噪）
   - 技术推测：DeepFilterNet 3 或 RNNoise

4. **CUDA Graph 移植**
   - 从 RVC 最新版移植
   - 降低 kernel launch 开销
   - **我们已经做了**

5. **全显卡支持**
   - NVIDIA / AMD / Intel 全系列
   - 混合型推理（低端显卡+CPU）

### 2.2 盒子变声器

**核心卖点：**
1. **咬字优化**
   - 需要导入本人 10-15 秒录音
   - 文件格式要求：wav，特定文件名
   - 技术推测：个人特征索引 + 实时校准

2. **RVCPRO 算法**
   - 声称比传统 RVC 效果更好
   - 具体技术细节未公开

### 2.3 泡泡变声器

**核心卖点：**
1. **咬字优化**
   - 录制 10 秒音频自动优化
   - 与盒子类似的方案

2. **破音哑音算法**
   - 情绪激动/大声说话不爆音
   - 技术推测：动态范围压缩 + 限幅 + 特征保护

3. **空气感效果**

### 2.4 真情实感变声器

**核心卖点：**
1. **咬字算法**
   - 必须导入本人 15 秒录音
   - 对录音质量有要求
   - 文件名和格式有严格要求

### 2.5 VST 插件版 RVC

**核心卖点：**
1. **超低延迟 40ms**
   - 直接挂载机架（VST3/AU）
   - 不需要单独打开 RVC 软件
   - 技术：JUCE 框架 + VST SDK + ASIO 驱动

2. **轻量化**
   - 同延迟下占用更低
   - 技术：C++ 推理核心 + 模型量化

3. **参数丰富**
   - gate 响应阈值（麦克风灵敏度）
   - mix（原声/变声平衡 0-100）
   - block 延迟大小
   - crossfade 弹入弹出

### 2.6 VCClient（日本 Okada 开源）

**特点：**
- 支持 RVC / DDSP 等多种模型
- 开源免费
- 安装有兼容性问题
- 对比 RVC 有轻微音损

|------|---------|---------|---------|--------|------|-----------|

| **FreeVC** | 零样本 | 5s参考 | 中 | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ |
| **VoiceCraft** | 零样本 | 参考音频 | 高 | ⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |

### 各路线技术特点

#### GPT-SoVITS
- **架构**：GPT（文本→语义特征）+ SoVITS（语义特征→音频）
- **优势**：零样本 TTS（5秒参考）、跨语种、情感丰富
- **劣势**：延迟高、显存需求大、不是纯 VC（是 TTS 路线）
- **可借鉴**：参考音频条件化、情感控制

#### Seed-VC
- **架构**：Diffusion Transformer (DiT) + 全参考音频上下文学习
- **优势**：零样本、高相似度、低 WER
- **劣势**：延迟高（扩散模型多步推理）、模型大
- **可借鉴**：全参考音频利用、音色泄漏缓解

#### DDSP-SVC
- **架构**：可微分数字信号处理（DDSP）+ 轻量神经网络
- **优势**：训练快、显存低
- **劣势**：音色泄漏明显、音质一般
- **可借鉴**：轻量合成方案

## 四、可借鉴的技术方案（按优先级排序）

### 🔴 高优先级（效果明显、改动可控）

#### 1. DeepFilterNet 3 CPU 降噪
**现状**：我们没有内置降噪，需要用户自己用 NVIDIA Broadcast 或其他软件。
**方案**：
- 纯 CPU 运行，RTF=0.19（单线程笔记本 CPU）
- 48kHz 全带降噪，效果优于 RNNoise
- 开源（MIT），Rust 推理路径，Python 绑定可用
- 不占 GPU，避免 GPU 降噪吞字问题
- **预期收益**：解决背景噪音问题，提升用户体验

#### 2. 咬字优化（特征时间轴校正）
**现状**：连续读"凤凰"等快速声调转折的词会咬字变怪。
**套皮方案分析**：
- 心月：自研算法，不公开细节
- 盒子/泡泡：导入本人录音做参考优化
**可能的技术方向**：
- **方向 A：F0-HuBERT 帧对齐**：确保 F0 和 HuBERT 特征从同一时间窗口提取，消除固定帧偏移
- **方向 B：输入侧特征归一化**：对 HuBERT 特征做轻度实例归一化（IN），剥离音色泄漏
- **方向 C：个人特征校准**：用用户短录音构建个人特征模板，实时推理时做偏移校正
- **预期收益**：解决"凤凰→废黄"、"宝宝→粑粑"问题

#### 3. 空气感效果（高频提升）
**现状**：我们之前做过但因为没声音被移除了。
**套皮方案**：心月独家功能，增加声音亮度和通透感。
**技术分析**：
- 本质：高频段 EQ 提升（6-16kHz）
- 不是简单的音量提升，而是频谱倾斜（spectral tilt）调整
- 正确做法：在合成后输出做高 shelf EQ，提升 6kHz 以上 3-6dB
- **预期收益**：增加声音质感，不发干不发闷

### 🟡 中优先级（需要较多开发）

#### 4. TensorRT 推理加速
**现状**：用 PyTorch eager 模式 + CUDA Graph。
**方案**：
- 合成器 + HuBERT 导出 ONNX → TensorRT FP16
- 预期加速 2-3x（从 20ms → 7-10ms）
- 挑战：动态 shape 处理、FP16 数值稳定性验证
- **预期收益**：降低推理延迟，支持更低 block_time

#### 5. 破音保护算法
**现状**：大声/情绪激动时会爆音/哑音。
**套皮方案**：泡泡变声器的"破音哑音算法"。
**技术分析**：
- 输入侧：动态范围压缩（DRC），限制输入峰值
- 输出侧：软限幅 + 峰值归一化
- F0 侧：大声时 F0 通常不稳定，需要更激进的中值滤波
- **预期收益**：提升鲁棒性，减少爆音

#### 6. VST 插件版本
**现状**：独立 GUI 应用。
**方案**：
- 用 JUCE 框架开发 VST3 插件
- C++ 推理核心（或嵌入 Python runtime）
- 延迟可降到 40ms（直接 ASIO 回调）
- **预期收益**：专业用户体验，挂载机架使用

### 🟢 低优先级（架构级改动）

#### 7. GPU 端 Faiss 检索
**现状**：Faiss 在 CPU 上检索。
**方案**：
- GPU k-selection 算法（NVIDIA 提出）
- HNSW 图索引（更高召回率）
- **预期收益**：减少 CPU-GPU 传输，降低延迟

#### 8. 共振峰增强（Formant Enhancement）
**现状**：有 formant 偏移参数（性别因子）。
**可借鉴**：
- 共振峰提升：80-200Hz 低频增加能量，增加"厚度"
- 多共振峰独立调整（F1/F2/F3）
- **预期收益**：更精细的音色控制

#### 9. Seed-VC / DiT 架构迁移
**现状**：NSF HiFiGAN 合成器。
**方案**：
- 用 Diffusion Transformer 替代 HiFiGAN
- 零样本能力（不需要训练模型，直接参考音频）
- **预期收益**：音质和相似度大幅提升，但延迟增加
