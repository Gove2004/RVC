## 一、咬字算法

### 1.1 问题本质

**现象**：连续读"凤凰""宝宝"等词时，咬字变怪（凤凰→废黄、宝宝→粑粑）。

**根本原因**：HuBERT 特征与 F0 帧时间轴不对齐，特别是快速声调转折处。

**技术细节**：
- HuBERT 输出 50fps 特征（每 20ms 一帧）
- F0 提取也是 50fps
- 但两者的帧偏移是硬编码的（如 pitch[3:-1]），没有随输入长度或 F0 方法动态调整
- 在平缓语音中，几帧偏移无感；但在"凤凰"的 V 型转折处（降调→升调），20-30ms 的偏移就意味着：
  - HuBERT 特征已经是"凰"的升调开头
  - F0 还停留在"凤"的降调结尾
  - 合成器收到音高和内容不匹配的输入 → 咬字变怪

### 1.2 套皮方案分析

#### 心月变声器 - 自研咬字算法
- **技术推测**：
  1. **输入侧特征归一化**：对 HuBERT 特征做轻度实例归一化（IN），剥离输入说话人的音色泄漏
  2. **帧对齐校正**：动态调整 F0 缓存与 HuBERT 特征的帧偏移
  3. **连续音节稳定性**：检测快速声调转折，在转折处平滑过渡

#### 盒子/泡泡变声器 - 录音参考优化
- **技术推测**：
  1. 导入用户 10-15 秒本人录音
  2. 从录音中提取用户的特征模板
  3. 实时推理时，用参考模板对输入特征做偏移校正
  4. 类似 index_rate 但用个人数据，而不是训练集数据

#### 行业共识
- **额外推理时长（extra_time）**：从 0.1s 增加到 1-3s，咬字明显改善
  - 原因：更长的上下文让 HuBERT 有更多信息判断当前音素
  - 代价：延迟增加、GPU 占用增加

### 1.3 可行实现方案（按复杂度排序）

#### 方案 A：增加上下文长度（最简单）
**原理**：extra_time 从 0.1s 增加到 1.0s+
**优点**：零代码改动，直接调参
**缺点**：延迟增加、GPU 占用增加
**预期效果**：咬字清晰度提升 30-50%
**我们现状**：用户已在调这个参数

#### 方案 B：F0-HuBERT 帧对齐校正
**原理**：动态调整 F0 缓存与 HuBERT 特征的帧偏移
**技术实现**：
```python
# 当前：硬编码 pitch[3:-1] = 28 帧
# 改进：根据 F0 方法和输入长度动态调整偏移

# 偏移量 = HuBERT 中心帧 - F0 中心帧
# RMVPE 通常有 1-2 帧的预延迟
# FCPE 通常有 0-1 帧的预延迟
offset = {
    "rmvpe": 1,   # RMVPE 有 1 帧中心延迟
    "fcpe": 0,    # FCPE 中心对齐
}[method]

# 写入缓存时用动态偏移
pitch[offset : offset + n_frames]
```
**优点**：延迟不增加，纯算法改进
**缺点**：需要仔细调偏移量，不同模型可能不同
**预期效果**：连续音节咬字改善 50-70%

#### 方案 C：输入侧特征归一化（轻度 IN）
**原理**：对 HuBERT 特征做轻度实例归一化，剥离音色泄漏
**技术实现**：
```python
# extract_features 之后、upsample 之前
strength = 0.3  # 轻度归一化（0=不归一化，1=完全归一化）
mean = feats.mean(dim=-1, keepdim=True)
std = feats.std(dim=-1, keepdim=True)
feats_normalized = (feats - mean) / (std + 1e-5)
feats = (1 - strength) * feats + strength * feats_normalized
```
**优点**：不增加延迟，减少音色泄漏
**缺点**：可能损失一些音色相似度
**预期效果**：音色泄漏减少，咬字更清晰

#### 方案 D：参考录音校准（盒子方案）
**原理**：导入用户短录音，构建个人特征模板，实时推理时做校正
**技术实现**：
1. 录制用户 10-15 秒清晰语音
2. 提取该录音的 HuBERT 特征统计量（mean/std per frame）
3. 实时推理时，用统计量对输入特征做标准化
**优点**：个性化校正，效果最好
**缺点**：需要用户录音，实现复杂
**预期效果**：咬字改善 70-90%

### 1.4 推荐实施顺序
1. ✅ 先试方案 B（帧对齐校正），零风险，立竿见影
2. ✅ 再试方案 C（轻度 IN），可调强度
3. 方案 D 作为高级功能，后续再做

## 二、空气感/气息感/不纯净感

### 2.1 问题本质

**现象**：AI 变声太干净，听起来"假"、"塑料感"、"电子感"。

**根本原因**：
1. **合成器输出太干净**：RVC 的 HiFiGAN 合成器输出的频谱过于平滑，缺少真实人声的高频细节和气息噪声
2. **缺少呼吸感**：没有自然的呼吸声和气流噪声
3. **频谱过于平坦**：真实人声有频谱倾斜（高频衰减），AI 输出过于平坦

**学术观点**：
- "AI 声音听起来假，99% 是因为太干净。真实人声有房间混响、轻微回声和频率不完美"
- "气息感 = 谐波衰减 + 2kHz 以上的吸气噪声"（IRCAM 研究）
- "白色噪声做的气声总是假的，因为相位分布和真实人声不同"（Source-Filter Vocoder 论文）

### 2.2 技术分析

#### 空气感 vs 尖锐感的区别
| 特征 | 空气感（Air） | 尖锐感（Harshness） |
|------|-------------|-------------------|
| 频率范围 | 6-16kHz | 2-5kHz |
| 听觉感受 | 通透、有质感 | 刺耳、粗糙 |
| 成因 | 高频轻微提升 | 中频尖锐峰 |
| 处理方式 | 高 shelf EQ 提升 | 动态 EQ 衰减 |

#### 气息感的声学本质
1. **谐波部分**：高频谐波衰减（频谱倾斜）
2. **噪声部分**：2kHz 以上的吸气噪声（aspiration noise）
3. **两者比例**：气息声越强，噪声占比越高

### 2.3 可行实现方案

#### 方案 A：高频 Shelf EQ（最简单）
**原理**：提升 6kHz 以上 3-6dB，增加"空气感"
**技术实现**：
```python
# 输出侧，合成后处理
# 用双二阶滤波器做 high shelf
from scipy.signal import iirfilter, sosfilt

# 6kHz 以上 shelf，+4dB
sos = iirfilter(2, 6000, btype='highpass', fs=sr, output='sos')
# 或者用 shelf filter 更精确
```
**优点**：实现简单，效果直接
**缺点**：可能引入尖锐感（harshness）
**注意**：
- 先衰减 2-5kHz 的尖锐峰，再提升 6kHz+ 的空气感
- 提升量控制在 3-6dB，不要太多

#### 方案 B：频谱倾斜调整
**原理**：调整频谱倾斜度（spectral tilt），模拟不同声门波形
**技术实现**：
```python
# 在频域做倾斜：每倍频程衰减/提升 n dB
# 正倾斜 = 高频多 = 更亮更通透
# 负倾斜 = 高频少 = 更暗更温暖

# 方法：用低通滤波器的截止频率调整
# 或者在 Mel 频谱上做倾斜，再重建
```
**优点**：更自然的高频调整
**缺点**：实现稍复杂

#### 方案 C：添加呼吸噪声层
**原理**：添加与输入相关的呼吸噪声，模拟真实人声的气流声
**技术实现**：
1. 从输入音频提取高频噪声成分（高通滤波 + 包络检测）
2. 按比例混合到输出
3. 噪声幅度与输入能量相关（大声时噪声多，小声时噪声少）

```python
# 1. 提取输入高频噪声
input_noise = highpass_filter(input_wav, 2000)  # 2kHz 以上
noise_envelope = abs(hilbert(input_noise))  # 包络

# 2. 按比例混合
breath_strength = 0.1  # 10% 噪声比例
output = output + breath_strength * noise_envelope * white_noise
```
**优点**：更真实的气息感
**缺点**：实现复杂，需要仔细调参

#### 方案 D：不纯净感（微失真/饱和）
**原理**：添加轻微的非线性失真，模拟真实电子设备的"温暖感"
**技术实现**：
```python
# 软削波（soft clipping）/ 磁带饱和
def soft_clip(x, drive=0.1):
    # tanh 饱和曲线，模拟电子管/磁带
    return np.tanh(x * (1 + drive)) / (1 + drive)
```
**优点**：减少"数字感"
**缺点**：可能引入失真，需要很轻微

### 2.4 推荐实施顺序
1. ✅ 先试方案 A（高频 shelf EQ），最简单，效果最直接
2. 再试方案 C（呼吸噪声层），更真实
3. 方案 D 作为高级选项，默认关闭

**关键注意**：
- 之前做空气感失败了（没声音），很可能是：
  1. 位置放错了（放在合成器输入而不是输出）
  2. 增益太大导致削波
  3. 滤波器设计错误（变成了低通而不是 shelf）

## 三、破音保护

### 3.1 问题本质

**现象**：大声说话/情绪激动时，输出爆音、哑音、破音。

**根本原因**：
1. **输入过载**：麦克风输入超过 0dBFS，数字削波
2. **F0 不稳定**：大声时声带振动不规则，F0 提取器输出不稳定
3. **合成器溢出**：输入特征能量过大，合成器输出溢出
4. **动态范围太大**：小声和大声差异大，模型训练时没见过这么大的动态范围

### 3.2 套皮方案分析

#### 泡泡变声器 - 破音哑音算法
- **技术推测**：
  1. **输入侧动态压缩**：大声时自动降低输入增益
  2. **输出侧软限幅**：输出接近 0dBFS 时平滑衰减
  3. **F0 稳定化**：大声时 F0 中值滤波更激进

### 3.3 可行实现方案

#### 方案 A：输入侧自动增益控制（AGC）
**原理**：检测输入音量，太大时自动降低增益
**技术实现**：
```python
# 输入侧，在特征提取之前
threshold = 0.5  # 最大输入幅度
max_gain = 2.0   # 最大增益

def agc(input_wav, target_rms=0.1):
    current_rms = sqrt(mean(input_wav^2))
    if current_rms > threshold:
        # 太大了，降低增益
        gain = threshold / current_rms
    else:
        # 太小了，提升增益
        gain = min(target_rms / current_rms, max_gain)
    return input_wav * gain
```
**优点**：防止输入过载
**缺点**：可能改变声音动态

#### 方案 B：输入侧硬限幅
**原理**：输入超过阈值时硬削波
**技术实现**：
```python
def hard_limit(input_wav, ceiling=0.95):
    return np.clip(input_wav, -ceiling, ceiling)
```
**优点**：最简单
**缺点**：硬削波会失真

#### 方案 C：输入侧软限幅（推荐）
**原理**：接近阈值时平滑衰减，不产生硬削波失真
**技术实现**：
```python
def soft_limit(x, ceiling=0.95, knee=0.1):
    """软限幅：超过 knee 后平滑压缩到 ceiling"""
    abs_x = np.abs(x)
    # 小于 knee 不处理
    mask_soft = abs_x > (ceiling - knee)
    # 软区：用 tanh 饱和
    x[mask_soft] = np.sign(x[mask_soft]) * (
        ceiling - knee + knee * np.tanh((abs_x[mask_soft] - (ceiling - knee)) / knee)
    )
    # 硬区：直接 ceiling
    x[abs_x > ceiling] = np.sign(x[abs_x > ceiling]) * ceiling
    return x
```
**优点**：无失真，平滑保护
**缺点**：需要仔细调参

#### 方案 D：F0 动态滤波
**原理**：大声时 F0 不稳定，用更激进的中值滤波
**技术实现**：
```python
# 检测当前帧能量
frame_energy = sqrt(mean(input_wav^2))

# 大声时用更大的中值滤波核
if frame_energy > high_energy_threshold:
    median_kernel = 5  # 大声时更激进
else:
    median_kernel = 3  # 正常

pitch = median_filter(pitch, kernel_size=median_kernel)
```
**优点**：减少大声时的 F0 抖动
**缺点**：可能引入延迟

#### 方案 E：输出侧峰值归一化
**原理**：输出峰值自动归一化，防止削波
**技术实现**：
```python
# 输出侧，SOLA 之后
peak = max(abs(output))
if peak > 0.99:
    output = output * (0.99 / peak)
```
**优点**：简单，防止输出削波
**缺点**：可能改变音量感知

### 3.4 推荐实施顺序
1. ✅ 方案 C（输入侧软限幅）：最简单，最有效
2. ✅ 方案 E（输出侧峰值归一化）：双保险
3. 方案 D（F0 动态滤波）：高级选项，默认关闭

## 四、综合实施建议

### 优先级排序

| 优先级 | 方案 | 预期效果 | 实现难度 | 延迟影响 |
|--------|------|---------|---------|---------|
| P0 | 咬字-方案 B（帧对齐校正） | 咬字改善 50-70% | 低 | 无 |
| P0 | 破音-方案 C（输入软限幅） | 消除爆音 | 低 | 无 |
| P1 | 空气感-方案 A（高频 shelf EQ） | 增加通透感 | 低 | 无 |
| P1 | 破音-方案 E（输出峰值归一化） | 双保险 | 极低 | 无 |
| P2 | 咬字-方案 C（轻度 IN） | 减少音色泄漏 | 中 | 无 |
| P2 | 空气感-方案 C（呼吸噪声层） | 更真实气息感 | 中 | 无 |
| P3 | 咬字-方案 D（录音校准） | 个性化校正 | 高 | 无 |
| P3 | 破音-方案 D（F0 动态滤波） | 大声更稳定 | 中 | +10ms |

### 关键风险提醒

**空气感方案**：
- 之前做过失败了（没声音），很可能是位置放错或增益太大
- 正确位置：**合成器输出之后、RMS 混合之前**（或之后，取决于想要的效果）
- 起始增益：+2dB，不要超过 +6dB
- 先衰减 2-5kHz 尖锐峰，再提升 6kHz+

**咬字方案**：
- 帧对齐校正需要仔细测试，不同模型可能偏移量不同
- 轻度 IN 的强度建议从 0.2 开始，不要超过 0.5
- 不要同时开太多功能，先逐个验证效果

**破音方案**：
- 软限幅的 knee 不要太大（0.05-0.1 即可）
- 输出归一化只在峰值超过 0.99 时触发，不要一直归一化
