## 0. 已知限制（如实，不放好看）

1. **只证「文本级零漂移」，不证「数值 / 时序等价」**：表能证明「某行改了 / 没改」，**不能**证明「改得对」。等价性仍只靠用户真机实跑。
2. **未覆盖 37 条无护栏项**（非 §3/§4/§10）：§1（1.3、1.8）；§2（2.4、2.8、2.9、2.11、2.16、2.19）；§5（5.1–5.6、5.11、5.12、5.19、5.33、5.35–5.37）；§6（6.1、6.14、6.15、6.18–6.22、6.24、6.25、6.28、6.33、6.39）；§7（7.1、7.19）；§8（8.29）。它们由 GUI/训练/autodl 驱动，本表**不覆盖**，回归仍只能真机暴露。
3. **`git diff -U0` 噪声**：对**纯移动 / 重排**显示为「删 + 增」，会把「只挪了位置」放大成多行变更，须人眼区分「重排（无害）」与「真改」。
4. **跨文件不显现**：若冻结函数的**调用顺序**被在另一文件里重排，本表（按文件切）不直接显现，需两侧文件同看。
5. **A-2 覆盖面缺口**：A-2 改 4 文件，其中 `rvc/core/config.py`、`rvc/streaming/engine.py` **不在**本 29 冻结集内（非数值冻结路径），其 `0.04`/`30` 两处不在表内 —— 但 A-2 **值不变**，风险低，靠 B2.5 普通 diff 复核。
6. **R-2 仍只兜「文本」**：`rvc/runtime/graph.py` 扩入后能看「捕获 / 回放代码是否被改」，**证不了 CUDA Graph 捕获 / 回放时序等价**。

## 3. 复核操作法（人眼）

1. 对每个文件：`git diff -U0 97c1fed..<rev> -- <单文件>`（逐条命令，不串联）。
2. **先看 A 组 18 个**：只要输出**非空** → 立即停手，逐行确认「本应零漂移」为何变了。
3. **再看 B 组 11 个**：把每个 hunk 对照本表「预期变更点」——**在预期点内** 判「一致」；**落在预期点外** 判「漂移」，必须解释。
4. 「重排型噪声」：若 hunk 是同表达式换行 / 缩进变化、**无值改动** → 判「重排（无害）」，仍须在行内注明。
5. **收口**：对 29 文件再跑一次 `base→head` 总表，确认最终态与逐批结论一致。
