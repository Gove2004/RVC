## 附录 D — `tracker.py` "前/后 p_len 帧" 语义推导（支撑 P1-2 / D-1）

1. **两者取自同一完整缓冲**：`f800ec3` 起，HuBERT 特征与 F0 都从完整 `state.input_wav_16k` 提取（`pipeline.py:200`、`tracker.py:50`），帧索引 0 都对应缓冲区起点。
2. **特征长度 = 对齐基准**：`postprocess_features` 先 upsample（`features.py:56-57`：末帧复制 + ×2 插值）得 `feats`，再 `ctx.p_len = feats.shape[1]`（`pipeline.py:171`）——即 `p_len` 由"完整 upsampled 特征长度"决定，**F0 必须逐帧贴合这个下标**。
3. **合成器按下标消费**：`infer_synth_audio` 把 `feats[0:p_len]` 与 `pitch[0:p_len]` 一同送入 `synthesizer.infer(..., skip_head, return_length, …)`；`skip_head` 只用于裁剪**输出音频**，不改变 `pitch` 与 `feats` 的**帧对帧**对应。故 `pitch[i]` 必须等于 `feats[i]` 同时刻的 F0。
4. **故取「前 p_len 帧」才对齐**：`f0_raw[i]` 与 `feats_up[i]` 都从缓冲起点计帧 → `f0_raw[:p_len]` 正确；取"最后 p_len 帧"会把尾部整体前移 `(n−p_len)` 帧，制造 F0↔特征错位。
5. **旁证**：行内注释（`tracker.py:54-55,58`）明确"特征是 upsample 后取前 p_len 帧，所以 F0 也应该取前 p_len 帧"；该 docstring 的"最后"措辞与理由属上一版滚动缓存设计的遗留心智模型（见 `git show f800ec3^:rvc/pipeline/pitch/tracker.py`，旧实现确以缓存**尾部**=`最近帧`为对齐点）。
6. **结论**：**代码正确，docstring 错误**。处置 = 修注释（行为不变）。仅当甲方另有意图时，改代码才成立，且属行为变更（D-1）。
