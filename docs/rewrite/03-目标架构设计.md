# 目标架构设计（阶段二）

> 原则：对外行为与《01-功能基线清单》逐条一致；内部结构自由度全权使用。
> 硬约束：零新第三方依赖；旧兼容层删净；依赖单向无环。

---

### 1.2 依赖规则（逐条封杀现状违规）

| 规则 | 封杀的现状问题 |
|---|---|
| models 只准依赖 core/runtime/dsp | P1-1 models→pipeline（hubert 用推理缓存、rmvpe 用 graph 回放）；P1-2 models→train（mel 函数） |
| pipeline 只准依赖 core/runtime/dsp/models/io | P1-3 pipeline→streaming（state 内嵌 AudioProcessor） |
| streaming 只准依赖 core/runtime/dsp/pipeline/io | ——（runner→pipeline.synthesis 合法保留） |
| train 只准依赖 core/runtime/dsp/models/io | —— |
| dsp/core/runtime 依赖 torch 但不依赖任何上层 | —— |
| 禁止函数内延迟 import 规避循环（出现即视为设计错误） | P1-4 registry↔extractor、engine↔pipeline、wav_file↔audio_file |
| autodl/gui 只准 import 各层公开门面符号 | P1-5 View 穿透四层私有属性；P1-6 monkey-patch 模块全局 |

### 1.3 关键结构决策

**D1. CUDA Graph 与 LRU 缓存下沉 runtime。**
现状：`runtime/cuda_graph.py`（设备判断/开关）与 `pipeline/cuda_graph.py`（捕获/回放/缓存池）分裂，models 反向 import pipeline。
目标：`runtime/graph.py` = 捕获/回放/缓存池（吸收 pipeline/cuda_graph.py 全部逻辑）+ `runtime/caches.py` = 通用 LRU（吸收 pipeline/cache.py 的 `_LRU`）。模型层（rmvpe/hubert/synthesizer）依赖 runtime，编码后推理缓存的具体槽位策略（hubert=2/rmvpe=1/...）留在 pipeline 组装层。

**D2. AudioProcessor 上移出 pipeline.state。**
现状：`pipeline/state.py:20` import streaming 的 AudioProcessor，跨块效果器藏在推理状态 dataclass 里。
目标：pipeline 的产物止于"合成音频块"；SOLA/RMS/输出路由全部归 streaming/runner。`EngineState` 只承载推理状态。数值行为不变（同一代码搬家）。

**D3. 纯 DSP 抽出 `dsp/`。**
`mix.py(fast_rms/apply_rms_mix)`、`alignment.py(apply_sola)`、`pitch/postprocess.py 的 hz_to_midi/midi_to_hz`、`train/mel.py(mel_filter_bank/pad_center)`、RMVPE 需要的窗函数 —— 全部无 torch 模型依赖的数学，进 `rvc/dsp/`。这是 train 不再被 models 依赖、且新单测可以直接打满的前提。

**D4. 显式参数替代 monkey-patch。**
- `audio_file.load_audio(..., ffmpeg_exe=None)`：默认取 `runtime.paths.FFMPEG_EXE`；autodl 显式传入定位结果。删掉"改写模块全局变量"。
- `Trainer(..., export_dir=None)`：默认 `MODELS_DIR`；autodl 传数据盘目录。删 `trainer_mod.WEIGHTS_DIR`。
- autodl `os.chdir` 从 import 时移到 `main()` 第一行（进程行为对向导自身等价；对外可观测的 cwd 影响仅存在于"把 autodl 当库 import"的场景——现状无人这么用）。

**D5. GUI 强制 View→Controller→(state/门面) 单向。**
- View 禁止 import rvc.*（唯一例外：类型注解）；四个页签全部经 controller/state 取数。
- 音高/延迟显示：controller 起一个 `RuntimeTelemetry` 只读快照对象，View 订阅，消灭 `engine._runner.pipeline.state.last_input_pitch` 四层穿透。
- 训练侧补 `TrainController`（现缺），三个工具 Tab 走 controller。
- `MainWindow` 拆分：窗口装配 / 信号绑定 / 生命周期（加载线程、托盘退出）三个职责单元，单文件 ≤300 行量级。

**D6. 配置单源。**
所有默认值只活在 `core/config.py` 的 dataclass 上；bindings 表、TrainGuiState、autodl DEFAULTS 全部从 dataclass 取默认，消灭三处漂移（FCPE/rmvpe、epochs 200/2000、lr 两种写法在 UI 层保持展示现状，仅内部默认值同源）。

**D7. 异常纪律。**
- 现状对外异常类型**全部保持**（wav_file 裸 ValueError、audio_file 的 FileNotFoundError/AudioLoadError 二元性、checkpoint 的 ValueError）——在函数 docstring 声明"为什么"。
- 新代码禁止 `except Exception: pass`；现状吞异常点逐一标注保留理由（stream 关闭、副输出丢帧）或改为记录（内部可观测，对外文案不变）。
- `ConfigError` 维持零抛出。

## 2. 命名规范

| 规则 | 示例（改 → 不改的理由） |
|---|---|
| 禁 Manager/Helper/Util/Commons/Misc/Data/Info 后缀与单词 | `ModelSessionManager` → `ModelSessions`；`nn/commons.py` → 按内容拆入 `nn/layers.py`（删恒 no-op 的 clip_grad_value_ 后剩余全是层构件）；`DeviceManager`→`DeviceCatalog`、`OfflineManager`→`OfflineConverter` |
| 阶段编号全局唯一一套，用角色名不用裸数字 | `stage_input / stage_features / stage_f0 / stage_synthesis / stage_output`（现三套并存 2-4/1-5/1-8） |
| 布尔词冠 is/has/should；动词开头为函数；dataclass 直述名词 | `enable_out2` 保留（行为字段名进 JSON，不动） |
| 领域专名保留 | `RMVPE`、`HuBERT`、`Synthesizer`、`SOLA`、`WASAPI` |
| 修正拼写错误 | `f0_rmvp_btn` → `f0_rmvpe_btn`（控件内部名，不进 JSON） |
| 模块名 = 单一职责名词 | `registry.py` → `sessions.py`；`loudness.py` 保留（内容即响度） |
| 拼写哨兵 | 副输出哨兵 `"不使用"` 保留（进 save_state.json，对外值） |

## 3. 算法层面改动（全部保证输出逐位/语义等价）

> 硬性前提：任何改动不得使离线转换 golden 输出偏差超过 ±1e-4（绝大多数应为逐位相等）。**不做**任何"更好听"的算法改进——那是对外行为变化。

| # | 改动 | 性质 |
|---|---|---|
| A1 | 删恒 no-op `clip_grad_value_` 及其两处调用 | 死代码，无输出影响 |
| A2 | SOLA 缓冲计算 `min(crossfade,4*zc)` 双实现合一 | 同公式 |
| A3 | RMVPE 阈值单源：`core/constants.py` 定义 `RMVPE_THRESHOLD_TRAIN=0.03`、`RMVPE_THRESHOLD_INFER=0.05`，两处显式引用 | 同值改名，消除"隐式双源" |
| A4 | `formant_factor` 声明为 InferenceContext 正式字段并纳入 reset | 修隐式契约，数值路径不变（每块必写） |
| A5 | 删 rmvpe STFT 死类、resample_kernel 死字段、n_gru 不可达分支、attn=None 残留 | 死代码 |
| A6 | spec 缓存迁出 `0_gt_wavs/` → `{exp}/spec_cache/`（已列基线第 9 节批准变化） | 唯一用户可感知项，mtime 失效语义保留 |
| A7 | `prefetch_input`/`_stage_input` 合一 | 同代码去重 |

## 4. 落地步骤（阶段三执行，分支 `rewrite-v2`，每步自证后提交）

| 步 | 内容 | 自证方式 |
|---|---|---|
| S0 | 建分支；用**旧代码**采集金标准：固定输入 wav 的离线转换输出（2 组参数）、小数据集训练 2 epoch 产物清单与 manifest、autodl 管道输入的逐行输出+退出码。存 `tests/golden/`（npy+sha256 清单） | 金标准存在且可复跑 |
| S1 | 新测试骨架：`python -m tests.run_tests` 改 unittest 自动发现；按基线 `[已有测试]` 语义重写 28 例（config/postprocess/mix），补 dsp/autodl 纯函数测试 | 全绿 |
| S2 | core+runtime 重组（graph/caches 下沉、paths/device 保留） | 单测 + import 图检查（禁反向） |
| S3 | dsp 抽取（mix/alignment/mel/hz_midi 搬家） | 新旧数值对比单测 |
| S4 | models 清理（A1/A5、依赖改 runtime/dsp） | 单测 + golden 离线对比 ±1e-4 |
| S5 | io（ffmpeg 路径参数化、异常点 docstring） | ffmpeg 缺失/损坏文件用例 |
| S6 | pipeline 重建（sessions/loader 改名、state 去 AudioProcessor、context 字段化 A4、stage 统一命名） | golden 对比 |
| S7 | streaming（runner 持有效果器、engine 瘦身、A2/A7） | golden 对比 + 延迟量级 |
| S8 | train（export_dir 参数化、A6 缓存迁移、checkpoint 互操作） | 训练小流程产物 diff + 旧 ckpt 互加载 |
| S9 | autodl（D4 参数化、chdir 入 main、管道测试） | 金标准逐行输出+退出码 diff |
| S10 | gui 重构（D5/D6、god class 拆分、tools 走 controller） | 逐页签人工清单走查 + save_state 往返等价 |

每步一条 commit，格式 `rewrite(Sn): 摘要 [自证方式+结果]`。GPU 环境不可用时 S0 金标准改由你在有卡机器跑一次采集。
