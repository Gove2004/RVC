### 关键架构决策

| 决策 | 内容 |
|---|---|
| A1 依赖方向 | 八层不变；AST 守护测试保留并扩充（新增：禁环境变量跨模块通信、禁访问 `_` 私有成员跨类） |
| A2 环境变量清零 | `RVC_CUDA_GRAPH` / `RVC_CUDA_GRAPH_MAX_CACHE` 删除 → `RuntimeOptions(use_cuda_graph, graph_cache_size)` 显式对象，从入口一路传入。⚠ 现状可用环境变量开关 graph，属未文档化行为，删除前需你确认（分歧点 D2） |
| A3 全局流副作用 | torchfcpe print 过滤、HuBERT 无控制台 devnull → 统一 `io_suppress` 上下文管理器，作用域内生效，退出恢复。对外可观测不变（控制台仍无噪声） |
| A4 引擎共享语义 | 离线/实时共用同一 runner **保持**（你已裁定）。process_file 进出的状态替换逻辑原样保留并写显式注释：调用契约 = 实时运行中不得调用离线 |
| A5 缓存语义 | 四槽 LRU 尺寸/键/失效条件逐字保持（基线 3.11），补测试锁定 |
| A6 死物 | 删：`tests/golden/offline_*.npy`+`manifest.json`、`log_interval`、`"models"` 骨架键、过时注释、`MAX_WAV_VALUE`。**保留**：上游目录、ffprobe.exe、rmvpe_inputs.pth（你已裁定） |
| A7 测试补强 | 新增：离线端到端（替换已死的金标准）、tracker 偏移锁定、RuntimeOptions 图开关、error_count 语义、无 GPU 中文报错文案 |

## 2. 命名规范（重写全程执行）

1. **禁用词**：类/模块/文件名禁 `data/info/manager/util/helper/common(s) 改名例外见下` 及一切无信息量词（`thing/stuff/tmp2`）。变量禁单字母（循环索引 i/j/k、数学公式内 n/m/x/y 除外）。
2. **自解释命名**：名称 = 职责 + 领域词。函数名动词开头（`extract_hubert_features`）；布尔变量/属性形容词化（`is_half`、`stop_requested`）；常量全大写带域前缀（`RMVPE_THRESHOLD_TRAIN`）。
3. **单一职责**：一文件一主题；>400 行需拆分并在模块 docstring 写拆分理由。
4. **错误显式化**：核心层只抛 `rvc/core/errors.py` 体系（裸 ValueError 仅 wav_file 处保持——GUI 契约，加注释声明）；禁止 except-pass，禁止 except Exception 后不记日志不转译。
5. **显式优于隐式**：禁模块级可变全局（现有 `_hubert_cache` 改为显式传入的缓存对象）；禁环境变量/monkey-patch 做参数传递；路径一律经 `paths.py`。
6. **依赖单向无环**：与 AST 测试同一条规则。

### 现有违例改名清单（语义不变，纯重命名）

| 现名 | 新名 | 理由 |
|---|---|---|
| `streaming/loudness.py` | `streaming/effects.py` | 名不符实（实为输出效果器） |
| `train/data_utils.py` | `train/dataset.py` | data+util 双违例；内容就是 Dataset |
| `gui/infer/controller/device_controller.py` 的 `DeviceManager` | `DeviceCatalog` | manager 违例；职责=设备枚举与查询 |
| `nn/commons.py` | `nn/vits_blocks.py` | commons 无信息量；内容即 VITS 通用块（分歧点 D3：改动原版拷贝层文件名，权衡见下） |
| `pipeline/sessions.py` 的 `get_f0_extractor` | 删除 | 死方法 |

> D3 说明：`rvc/nn/` 与 `models/` 是原版 RVC 数值路径拷贝，重命名文件不改变数值，但增加与上游对照的 diff 成本。默认执行改名；若你想让 nn/models 层与上游逐文件可对照，则保留原名。
